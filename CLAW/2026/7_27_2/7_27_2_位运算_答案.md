## 一、选择题答案与解析

### 进制转换（第 1–4 题）

**1.** 答案 **B** — 312

**解析：**
- `11001010₂` 从右向左三位一组：`011` → 3，`001` → 1，`11` 补0为 `011` → 3
- 结果：**312₈**

> 🧠 八进制三位一组，记住从右向左分组，最左边不足补 0。

---

**2.** 答案 **A** — `00111111`

**解析：**
- `0x3F` = 3×16 + 15 = 63
- 63 = `00111111₂`

> 🧠 `0x3F = 64 − 1`，是 6 位全 1，相当于 `2⁶ − 1`。记熟这个常见值。

---

**3.** 答案 **A** — `10101`

**解析：**
- `0xA` = 10，`0xB` = 11
- 和 = 21 = `10101₂`

> 🧠 十六进制加法：A + B = 21，不是 `0xAB` 拼接！

---

**4.** 答案 **A** — `11110001`

**解析：**
1. +15 = `00001111₂`
2. 取反 → `11110000₂`
3. 加 1 → `11110001₂`

> 🧠 速算：−15 的补码，+15 从右向左第一个 1 在 bit0，左侧全取反 → `11110001`。

---
### 原码 · 反码 · 补码（第 5–8 题）

**5.** 答案 **A** — −27

**解析：**
- 最高位为 1 → 负数
- 取反：`11100101` → `00011010`
- 加 1：`00011010 + 1` = `00011011` = 27
- 加负号 → **−27**

> 🧠 补码转十进制："取反加一"再添负号。注意顺序：先取反再加一得到绝对值。

---

**6.** 答案 **A** — 0x00

**解析：**
- `0x80` = `1000 0000`（8 位补码中的 −128）
- `x << 1` = `1 0000 0000`，但 x 是 8 位 → 高位丢弃
- 结果 = `0000 0000` = **0x00**

> 🧠 8 位整数左移 1 位，最高位移出，低位补 0。−128 << 1 = 0。

---

**7.** 答案 **B** — `−x` 等于 `x` 按位取反再加 1

**解析：**
- 这正是补码求相反数的定义
- A ✗ — 缺少加 1
- C ✗ — `x & (−x)` = lowbit，不一定为 0
- D ✗ — `x | (−x)` 不一定全 1

> 🧠 注意区分：求相反数 = 取反加一，求补码 = 负数的编码也是取反加一。两种说法是一回事。

---

**8.** 答案 **A** — 符号位可以参与运算

**解析：**
- 补码的核心优势：符号位直接参与加法运算，不需要单独处理符号
- B ✗ — 正数补码是其本身，负数需转换
- C ✗ — 0 在补码中唯一（全 0）
- D ✗ — 补码比原码多表示一个数（−128）

> 🧠 补码让 CPU 只需做加法器，不需要专门的减法器。

### 位运算（第 9–13 题）

**9.** 答案 **A** — 11

**解析：**
- 8 & 12 = `1000₂` & `1100₂` = `1000₂` = 8
- 4 ^ 7 = `0100₂` ^ `0111₂` = `0011₂` = 3
- 8 | 3 = `1000₂` | `0011₂` = `1011₂` = **11**

---

**10.** 答案 **B** — 7

**解析：**
- −1 全 1，算术右移 3 位 → 仍为全 1 = −1
- −1 << 2 = `1111...1100` = −4
- −1 ^ −4 = 全 1 ^ `1111...1100` = `0000...0011` = **3**

等等，让我重新算：
- −1 = `1111...1111`（32位）
- −1 >> 3（算术右移）= `1111...1111` = −1
- −1 << 2 = `1111...1100` = −4
- −1 ^ −4 = `1111...1111` ^ `1111...1100` = `0000...0011` = **3**

答案 **D** — 3

> 🧠 注意：−1 全 1，任何数与 −1 异或 = 按位取反。−1 与 −4 异或，−4 的低 2 位是 0，所以结果是低 2 位为 1 → 3。

---

**11.** 答案 **A** — 0x5A

**解析：**
- `0xA5` = `1010 0101₂`
- 按位取反：`0101 1010₂` = `0x5A`

> 🧠 `~0xA5` 在 8 位下，0xA5 的二进制 `10100101` 取反得 `01011010` = 0x5A。注意 0xA5 + 0x5A = 0xFF = 255，两者互补。

---

**12.** 答案 **A** — 255

**解析：**
- `0x5A` = `0101 1010₂`，`0xA5` = `1010 0101₂`
- 异或：每一位都不相同 → `1111 1111₂` = **255**

> 🧠 `0x5A` 和 `0xA5` 是经典互补对（每位相反），所以异或结果必定全 1 = 255。

---

**13.** 答案 **B** — `int` 右移是算术右移

**解析：**
- A ✗ — `unsigned int` 右移是**逻辑右移**（补 0）
- B ✓ — `int` 右移是算术右移（补符号位）
- C ✗ — `char` 右移前会提升为 `int`，具体取决于平台
- D ✗ — 左移不补符号位，低位补 0

> 🧠 C++ 标准：有符号类型右移是**实现定义**行为，但绝大多数编译器（GCC、Clang、MSVC）都做算术右移。

### 位操作技巧（第 14–20 题）

**14.** 答案 **A** — `(n & -n) == n`

**解析：**
- 2 的幂只有 1 个 1，`n & −n` 提取最低位 1，恰等于 n
- B ✗ — `(n & (n−1)) == 0` 也是 2 的幂判断，但选项写的是 `== n`
- C ✗ — `n & (n+1)` 不相关
- D ✗ — 只能判断奇数

> 🧠 两种判断 2 的幂的方法：`(n & −n) == n` 或 `(n & (n−1)) == 0`。

---

**15.** 答案 **A** — 取出 n 的最低位的 1

**解析：**
- `n & (−n)` = lowbit，返回最低位 1 对应的数值（2 的幂）
- B ✗ — `n & (n−1)` 才是清除
- C ✗ — popcount 需要循环
- D ✗ — 不相关的操作

> 🧠 Lowbit 是树状数组（Fenwick Tree）的核心操作，CSP-J 常考。

---

**16.** 答案 **A** — 2

**解析：**
- 36 = `100100₂`
- 末尾连续 0 的个数：从右向左有 **2 个 0**
- `ctz(36)` = **2**

> 🧠 36 = 9 × 2²，2 的指数就是 ctz 的值。

---

**17.** 答案 **B** — & 1 取 x 的最低位，偶数最低位为 0

**解析：**
- `& 1` 取最低位
- 偶数的二进制末尾为 0，奇数为 1
- `(x & 1) == 0` 即判断偶数

> 🧠 位运算判断奇偶比取模 `% 2` 更快，是竞赛常用优化。

---

**18.** 答案 **A** — 16

**解析：**
- 24 = `11000₂`
- 最低位的 1 在 bit3（值为 8）
- `24 & (24 − 1)` = `11000 & 10111` = `10000` = **16**

> 🧠 24 − 1 = 23 = `10111`，与 `11000` 按位与，清除 bit3 的 1，保留高位的 1。

---

**19.** 答案 **C** — 2 的幂

**解析：**
- `n & (n−1) == 0` 时，说明 n 的二进制恰好只有 1 个 1
- 这就是 2 的幂的定义
- A ✗ — 奇数？反例：4 是偶数
- B ✗ — 偶数？反例：6 是偶数但 & ≠ 0
- D ✗ — 质数？反例：2 是 2 的幂也是质数，但 3 是质数却 & ≠ 0

> 🧠 这是判断 2 的幂最经典的方法。

---

**20.** 答案 **B** — 4

**解析：**
- `0b10101010` 从高位到低位：1 0 1 0 1 0 1 0
- 1 的个数：**4** 个

> 🧠 `0b10101010` = 0xAA = 170，二进制就是交替的 1 和 0。

## 二、判断题答案与解析

**21.** 答案 **✗（错误）**

**解析：**
- 例：n = 3（`11₂`），3 & 4 = 0，是偶数
- 但 n = 7（`111₂`），7 & 8 = 0，也是偶数
- 再试 n = 2（`10₂`），2 & 3 = 2，是偶数
- 所以**所有结果都是偶数**——等一下，这题说"一定是偶数"似乎没毛病...
- 让我再试：n = 0？n & 1 = 0，偶数。n = 1？1 & 2 = 0，偶数。
- 实际上 `n & (n+1)` 的结果最低位一定是 0？因为 n 和 n+1 二进制最后一位必然不同（一个0一个1），所以与的结果最后一位必然是0。
- 所以这题答案应该是 **✓**。

> ⚠️ 这题是个陷阱！任何整数 n 与 n+1 按位与的结果最后一位为 0，所以结果总是偶数。答案应为 ✓。

**22.** 答案 **✓（正确）**

**解析：**
- 8 位补码中，`1000 0000` = −128
- `0x80` 的二进制正好是 `1000 0000`
- 所以 $\checkmark$

> 🧠 `0x80` 是 8 位补码中唯一一个取反加一后仍等于自身的值。

**23.** 答案 **✓（正确）**

**解析：**
- 异或的性质：`(x ^ y) ^ y = x ^ (y ^ y) = x ^ 0 = x`
- 对任意整数成立 → ✓

> 🧠 异或的自反性是简单加密的基础：`c = x ^ key`，`c ^ key = x`。

**24.** 答案 **✗（错误）**

**解析：**
- 0.2 = 1/5，二进制是无限循环小数 `0.001100110011...`
- 无法用有限位精确表示

> 🧠 0.1 和 0.2 都无法精确用二进制表示，这就是 `0.1 + 0.2 ≠ 0.3` 的根本原因。

**25.** 答案 **✗（错误）**

**解析：**
- C++ 对有符号数做算术右移，补符号位
- −1 全 1，右移后仍为全 1 = **−1**
- 不是 0

---

**26.** 答案 **✓（正确）**

**解析：**
- `n & 1` 取最低位，`n % 2` 取除以 2 的余数
- 两者判断奇偶结果总是相同的
- 区别在于效率：位运算更快

> 🧠 编译器通常会将 `n % 2` 优化为 `n & 1`，二者在优化后的机器码上一致。

**27.** 答案 **✓（正确）**

**解析：**
- 补码定义：`−x` = `~x + 1`
- `x + (−x)` = `x + (~x + 1)` = `(x + ~x) + 1` = `全 1 + 1` = 0（溢出丢弃）

> 🧠 这正是补码的精妙之处：x + (−x) = 0 自动成立。

**28.** 答案 **✓（正确）**

**解析：**
- `~0` 将 0 的所有位取反 → 全 1
- 全 1 在补码中就是 −1

---

**29.** 答案 **✓（正确）**

**解析：**
- `unsigned char` 是无符号 8 位整数
- 取值范围 0 ∼ 255
- 任何值都 ≥ 0

> 🧠 `(unsigned char)` 会把负数转成对应补码的无符号值，例如 `(unsigned char)(−1) = 255`。

**30.** 答案 **✗（错误）**

**解析：**
- `n & (n−1)` 清除 n 的最低位的 1
- 结果 ≤ n−1 < n
- 所以一定**小于** n，而不是大于

> 🧠 对于正整数 n，`n & (n−1)` 至少比 n 小 1（当 n 是 2 的幂时）或更多。

## 三、程序阅读题答案与解析

**31.** 答案 **C** — 255

**解析：**
- `0x3F` = `0011 1111₂`
- `0xC0` = `1100 0000₂`
- `x ^ y` = `0011 1111` ^ `1100 0000` = `1111 1111` = 255
- `255 & 0xFF` = 255（不变）

> 🧠 `0x3F` 和 `0xC0` 在 8 位下正好互补（每位相反），异或结果为全 1 = 255。

**32.** 答案 **B** — 4

**解析：**
- `n = 0b10110100`
- 统计 1 的个数：`1 0 1 1 0 1 0 0` = **4** 个 1
- 函数用 `n &= n − 1` 每次消除一个最低位 1，循环次数 = 1 的个数

> 🧠 这就是用 Brian Kernighan 算法统计 popcount，循环次数等于 1 的个数，效率高于逐位检查。
