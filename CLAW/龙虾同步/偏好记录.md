## 二·五、编程题出题规范（HUSTOJ 批量出题）

### 提示（hint）规范
- **提示里仅仅提醒数据范围**（如 `n 的取值范围：10 ≤ n ≤ 1000`、溢出/精度提醒）
- **不要讲解解题思路**，不要写伪代码，不泄露任何解法

### 出题流程
1. 先确认知识点与难度（如刚学完 for 的学生）
2. 列题型谱系给用户选，避免经典套路题（角谷、蜗牛、gcd、调和级数等用户题里已有）
3. 用户确认题目描述后再造样例
4. 生成 HUSTOJ FPS XML（测试数据用明文，不要 base64——HUSTOJ 导入源码 mkdata() 直接 fputs 写入，不解码 base64，编码会导致测试数据乱码）

### 数值设计注意
- 默认 int，溢出风险题（如翻倍类）提醒 long long
- 比例衰减题注意答案是否与输入无关（如固定比例×固定阈值 → 答案恒定，需调整条件使输入有意义）

### 生成必查项（2026-08-03 新增，防漏）

生成刷题网页时**必须**替换以下占位符，并最后 grep 检查无残留：

1. `<title>${标题} · 练习</title>`
2. `app-header` 里的 `<h1>${标题}</h1>`（页面大标题）
3. `app-header` 里的 `<p>${副标题/知识点列表}</p>`（知识点概览）
4. 分值文案（模板里硬编码的"每题 4 分，总分 100 分"要改成实际题量和分值）
5. 生成后检查：`grep -c '${' 刷题.html` 应只剩 JS 模板字符串，不得残留 `${标题}`、`${副标题}` 等

> 教训：曾因只替换 `<title>` 漏掉 app-header 的两个占位符，页面顶部标题/副标题空白。

### 模式

1. 📝 **练习（Practice）** — 逐题作答，← → 翻页，可反复改选项，交卷后弹出结果报告（含得分/正确率/用时/错题列表），结果报告中显示刷题密码。练习模式下选项**无抖动动画**（`.no-feedback` 类），**不实时显示对错解析**。
2. ⚡ **刷题（Quiz）** — 需 6 位密码才能进入，选完立即显示对错 + 展开解析，选错时选项**有 shake 抖动动画**（仅刷题模式）。可前后翻页、反复改选项。

### 功能边界
- **无** 背题模式
- **无** 错题本（只有练习报告里展示本次错题列表）

### 交互方式
- 一次只展示一题
- 通过进度条（圆点）+ 上一题 / 下一题按钮导航
- 点击进度条可跳转

### 密码处理
- 硬编码 `const PASSWORD = "***";` 在 HTML 里，固定不变
- 密码显示在练习结果报告的弹窗中

### 结果报告
- 练习交卷后弹出模态框，显示：
  - 得分 / 总分
  - 正确分、错误分、正确率%
  - 用时秒数
  - 错题列表（可展开）
  - 「进入刷题模式看答案」按钮
  - 「重新练习」按钮
- 点击「进入刷题模式看答案」→ 清空练习答案、自动解锁刷题模式并跳转

### 判断题专项要求（2026-08-06 新增，防回归）

**数据格式**
- `"type":"judge"`，`"options":["✓ 正确","✗ 错误"]`，`"answer":"A"`（正确）/`"B"`（错误）

**显示（硬规则）**
- 所有展示正确答案的位置（错题报告、结果弹窗）必须显示**选项文本**（`✓ 正确` / `✗ 错误`），**禁止显示字母 A/B**
- 取判断题正确项按下标：`q.answer === 'A' ? 0 : 1`；**禁止**用 `q.options.find(o => o.startsWith(q.answer + '.'))`——判断题选项无字母前缀，会 fallback 成字母（曾致错题报告显示"正确：B"）

**解析（硬规则）**
- 判断题必须有**完整解析**（正确/错误原因 + 结论 + 考点），**禁止只有 `【考点：...】` 占位**
- `习题_答案与解析.md` 中判断题解析为**正文形式**（`**N.** 答案 **✅ T**` + 原因说明 + `> 考点：`），不是表格；生成脚本 `parse_answer()` 对判断题提取正文（选择题才解析表格行+考点），2026-08-06 已修复
